CALLDINE — VIDEO PRESENTATION SCRIPT

1. COMPLETE SYSTEM ARCHITECTURE

Introduction
“This is CallDine, an AI restaurant assistant. Customers can ask questions, place orders, and book tables through chat or voice. This diagram shows how the application, AWS services, and databases work together.”

Application and database
“The interface uses Next.js. Requests go to FastAPI, which coordinates the AI services and restaurant operations. SQLite stores information such as users, conversations, orders, reservations, and processing jobs.”

Restaurant knowledge
“An admin uploads a restaurant PDF. The backend stores it in Amazon S3 and uses Textract to extract the text. It splits the text into chunks, creates embeddings with Amazon Titan, and stores those embeddings with the source text in Qdrant.”

AI and business tools
“Amazon Bedrock runs the conversation model. When it needs restaurant information or an action, it requests a tool. FastAPI executes that tool and returns the result, so the assistant can give an answer.”

Voice conversation
“The browser captures the customer’s speech. FastAPI sends the audio to Amazon Transcribe, then the transcript goes through the chat workflow. Amazon Polly turns the answer into speech, and the browser plays it back.”

Guardrails
“CallDine supports optional Amazon Bedrock Guardrails. When configured, these policies can filter prompt-injection attempts, harmful content, and blocked words. The actual protection depends on the policy configured in AWS.”

Recordings and storage
“The browser can combine the microphone and assistant audio into a call recording. FastAPI saves the recording in S3 and keeps its reference in SQLite. S3 also stores restaurant PDFs and menu images.”

Planned forecasting
“SageMaker forecasting is a planned extension. It would use historical demand to predict future demand and support restaurant preparation. The current dashboard uses demonstration values.”


2. DETAILED WORKFLOW — KNOWLEDGE BASE PIPELINE

Step 1 — Upload the PDF
“The admin uploads a PDF containing restaurant information, such as policies or frequently asked questions.”

Step 2 — Store it in Amazon S3
“FastAPI stores the original PDF in Amazon S3 and creates a processing record.”

Step 3 — Extract text with Textract
“Amazon Textract reads the document. FastAPI retrieves the extracted text.”

Step 4 — Split the text into chunks
“The backend divides the text into smaller chunks of about one thousand characters.”

Step 5 — Create Titan embeddings
“Amazon Titan Text Embeddings V2 converts each chunk into a numerical vector. This embedding helps the system search by meaning.”

Step 6 — Store embeddings in Qdrant
“Qdrant stores the embeddings, original text, and document metadata. The restaurant knowledge is now ready for search.”

How the knowledge is used
“When a customer asks a question, FastAPI creates an embedding for that question and searches Qdrant. It returns the most relevant text to Bedrock, which uses it to answer. This process is called retrieval-augmented generation, or RAG.”


3. DETAILED WORKFLOW — COMPLETE VOICE CONVERSATION

Chime setup
“FastAPI creates the meeting and attendee. The browser joins using the Amazon Chime SDK. The assistant captures microphone turns separately for speech processing.”

Step 1 — Customer speaks
“The browser captures the customer’s speech. After a short silence, it uploads the audio through Next.js to FastAPI.”

Step 2 — Amazon Transcribe
“FastAPI sends the audio to Amazon Transcribe Streaming, which converts the speech into text.”

Step 3 — Transcript to FastAPI
“The transcript returns to the browser, which sends it to the FastAPI chat service with the conversation context.”

Step 4 — Guardrails input check
“When configured, Amazon Bedrock Guardrails checks the input text as part of the Bedrock request. Its policies can filter prompt attacks, harmful content, and blocked words.”

Step 5 — Bedrock LLM
“Allowed input reaches our language model in Amazon Bedrock. The model uses the conversation context and selects tools when it needs information or an action.”

Step 6 — FastAPI runs tools
“FastAPI executes the selected tools, such as knowledge search, menu search, orders, or reservations. It returns the results to the model. If no tool is needed, the model can answer directly.”

Step 7 — Answer and Guardrails
“Bedrock generates the response from the conversation and tool results. The configured Guardrails policy can also check the response text. If the policy intervenes, the application returns a blocked response.”

Step 8 — Polly and playback
“The browser requests speech for the returned text. FastAPI calls Amazon Polly, and the browser plays the MP3 response before listening again.”

Implementation clarification
“Guardrails is part of the Bedrock requests in this project. It is shown before and after the model to explain the checks, but FastAPI does not make a separate Guardrails call. The policy is optional, and its deployed settings have not been verified.”

Presenter reference
Guardrails does not evaluate tool definitions, tool-call arguments, or tool-result fields in the Converse API. FastAPI services perform the business validation. Chime meeting media is separate from the microphone-turn uploads to Transcribe.
Source: https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-use-converse-api.html
Code: backend/app/services/chat_service.py; backend/app/services/voice_service.py; Frontend/components/voice/VoiceAssistant.tsx


4. DETAILED WORKFLOW — AI TOOLS AND GUARDRAILS

Introduction
“Tools connect the AI conversation to restaurant data and actions. Bedrock selects a tool, and FastAPI executes it.”

search-knowledge
“This tool uses RAG to find restaurant information from the uploaded PDFs.”

search-menu
“This tool finds dishes, prices, availability, and stock.”

check-order-items
“This tool checks item quantities, available stock, and the order subtotal.”

create-order-draft
“This tool saves an order draft after the delivery address is approved.”

confirm-order
“This tool rechecks stock, confirms the draft, and updates inventory.”

check-table-availability
“This tool checks table capacity and overlapping reservations.”

create-reservation-draft
“This tool saves the booking details as an unconfirmed reservation.”

confirm-reservation
“This tool rechecks availability, assigns a table, and confirms the booking.”

Bedrock Guardrails
“Optional Guardrails policies can filter prompt attacks, harmful or toxic content, and blocked words. CallDine can attach a configured policy to its Bedrock chat calls and handle blocked responses. The deployed policy has not been verified.”


5. DETAILED WORKFLOW — PLANNED SAGEMAKER FORECASTING

Introduction
“This is the planned forecasting workflow. It is separate from the conversational AI and is not connected in the current application.”

Step 1 — Prepare historical data
“Historical orders would be grouped by day and menu category.”

Step 2 — Store the dataset in S3
“The prepared time-series dataset would be stored in Amazon S3.”

Step 3 — Train DeepAR
“Amazon SageMaker would train and evaluate a DeepAR forecasting model.”

Step 4 — Predict demand
“The model would predict category demand for the next seven days, with prediction ranges.”

Step 5 — Apply business rules
“FastAPI would translate the forecast into preparation and inventory recommendations.”

Step 6 — Display results
“The admin dashboard would show the forecasts and recommendations to the restaurant team.”

Closing
“Together, these workflows show how CallDine combines restaurant knowledge, conversational AI, voice services, and business tools, with forecasting planned as a future addition.”
